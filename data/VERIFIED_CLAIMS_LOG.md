# Verified Claims Log

A running record of specific factual claims that have already been independently checked
against a primary source, so the `fact-checker` agent doesn't re-verify the same claim from
scratch every time a page is edited. Added October 2026 after noticing the same Lewisham
Housing Strategy figures (rent/income growth, biggest-cause-of-homelessness) got verified
twice in one session.

**This file is written to by two agents, not by hand:**
- `fact-checker` appends a new row whenever it independently verifies a claim that isn't
  already logged (or logs it as DROPPED/PENDING when a claim fails or can't be confirmed).
- `update-scanner` may flip an existing row's **Status** from VERIFIED to STALE (with a note
  on what's newer) when it finds a newer release for a `Periodic` source - but it does not
  rewrite the claim or figure itself; that still requires a fresh fact-checker pass.

**Why a log, not just re-trusting old page text**: §2.2 of `DIMENSION_PAGE_SPECIFICATION.md`
already requires auditing every inherited claim, including old ones, because this project has
shipped fabricated/mis-attributed numbers that sat unnoticed for weeks (see Bad example #5).
A log doesn't remove that discipline - it just means "already checked, here's when and
against what" is recorded in one place instead of re-derived from scratch, and makes it
possible to tell a merely-old verification from a genuinely current one.

## Schema

| Column | Meaning |
|---|---|
| Claim | The exact figure/claim, close enough to match on re-check (geography + year + number) |
| Dimension / Indicator | Which page section this supports |
| Source | Document/dataset name |
| URL | Primary source link (not a secondary summary) |
| Source type | `Static` (historical document/report, won't be revised) or `Periodic` (recurring release - re-check cadence applies) |
| Status | `VERIFIED` / `STALE` (newer round exists, needs re-check) / `DROPPED` (checked, found wrong/unconfirmed, removed from live copy) / `PENDING` (not yet independently confirmed - do not treat as PASS) |
| Verified | Date last confirmed against the primary source |
| Notes | Anything a future check needs to know - how it was extracted, caveats, what superseded it if STALE/DROPPED |

**A `Periodic` source type does not mean "skip re-checking forever"** - it means the fact-
checker should still confirm the *current* figure is still the latest round before citing it
as fresh (e.g. "is 2024 still the newest Annex Table 1 release, or has 2025 landed?"), even if
the number itself hasn't changed round to round. `Static` sources (a one-off council strategy
PDF, a specific year's Census table) can be trusted without a freshness re-check - only a
correctness re-check if the claim text changes.
